## 2. 记忆交给 Hermes

**根因（实测）**：抓包看到壳每轮请求带 `messages.length = 34`：一条 system（990 字）＋ 整段 user/assistant 历史（带 `[2026-09-15 15:44]` 时间戳），连 `User encountered error: Failed to fetch` 这种错误行都回灌。Hermes 侧自己也存着一条会话历史 → 上下文双份。

**耦合点（已定位）**：`packages/stage-ui/src/stores/chat.ts` —— `toProviderHistory()`（L82，已会过滤 `role: 'error'`）组装出站消息，L229 `llmStore.stream(model, chatProvider, messages, …)` 发出去。壳本地的 `messages` 就是它自己的完整对话（展示用）✓。

**做法（与"壳里能翻完整对话"不冲突：本地照存，只是发出时不带）**：
- [x] 出站只带**最新一条 user 消息**：`chat.ts` 的 `streamWithStageAdapters` 里加 `outboundMessages`（`messages.filter(role==='user').slice(-1)`）并替换 `llmStore.stream` 与 span 属性；本地 store 不动。
- [x] 同时补 `X-Hermes-Session-Id: albion-desktop` 固定头——**这一步不能省**：Hermes 的会话 id 默认由「system prompt + 首条 user」推导，只发一条消息时若不带头，每轮都会开新会话、上下文就断了（源码：`api_server_openai_routes.py`，带 `X-Hermes-Session-Id` 才从 state.db 续历史）。
- [x] 实测：探针抓到 `messages.length=1` + 头 `albion-desktop`；直连两次（只发单条）问「草莓放哪」她答得出 → 会话延续成立。
- [x] 壳的 `memory-short-term` / `memory-long-term` 页面与入口已删（pgvector 记忆不再启用）。
- [x] 角色卡 `description` 精简成 112 字（人格交给 SOUL）——已完成并抓包验证（不再发那 1450 字的 AIRI 人格）。
- [ ] 回灌时过滤掉 `User encountered error: ...` 这类系统噪声行。

**验收**：抓包（临时转发探针）看请求里 `messages.length == 1`（只有最新那条 user）；她仍能记住上一句说的内容（走 Hermes 会话）。

### 8.2 ⑤ 追加：空闲循环的"断一下"＝模型接缝（已修，2026-09-15）

**你反馈"断一下还在、空闲循环里总是加速跳到下一个画面"→ 录屏 + 逐帧差分定位到了真凶：**

用 CDP screencast 录 30 秒 + 每帧采样模型参数（`_idle_probe.mjs`），把帧缩到 160px 算相邻帧差：

```

      最剧烈的帧出现在 2.49s、11.52s、20.55s、29.58s —— 间隔 9.03s ↔ 正好是 idle 动作的 Duration 9.0
修后: 中位 0.435 / p99 0.985 / max 2.019，且不再有 9 秒周期

**根因不在我们代码，在模型资产**：`idle.motion3.json`（以及 idle1..5、touch_idle1..10，共 16 个 `Loop: true` 的动作）**首尾帧根本没对齐**——640 条曲线里 362 条的首尾值差 >0.4，最狠的是头发/衣摆的 `Param_Angle_Rotation_*`，差 **69.5°**（touch_idle8 差 139.8°、touch_idle6 差 263.7°）。也就是说这些动作是**按"播一次就走"设计的**，被标成循环后每 9 秒硬跳回开头 = 你看到的"断一下 / 跳到下一个画面"。

**修法（改资产，不改代码）**：`_patch_seam.py` —— 对每个循环动作的每条曲线加一条线性漂移 `delta·t/D`（`delta = 首值 − 尾值`），末尾没到 D 就在 D 处补一个关键点＝首值。贝塞尔控制点同步漂移，阶梯段的开关语义不受影响。
```

（16 个循环动作共修 6185 条曲线；改后所有动作首尾差 = 0）
备份: albion.zip.bak-seam
```
同时**撤掉了**上一版加的运行时"接缝遮罩"（定时重起动作那套）——既然曲线本身接上了，运行时那套是多余复杂度。

**没动**：`Loop: true` 保持（现在循环是真无缝了）、动作轮播仍然不做。

### 8.3 ⑤ 再追加：剩下的"跳"是**速度**不连续（已修，2026-09-15）

你指出"1-2 秒、19-20 秒空闲里还有跳"。这次换了更硬的量法：**每帧遍历模型全部 759 个参数 + 201 个部件不透明度，只记录"这一帧里最大的单参数突变量"**（`_paramwatch.mjs`），比帧差灵敏得多（一帧里的姿态跳变必然落在某个参数上）。

```

### 9.6 空闲动画与作者对齐：变体轮播 + 循环顺（2026-09-15 晚）

**指挥官反馈**：「闲时动画能跟作者设置的那样吗？现在的动画没有闪光点，循环也不流畅。」

**根因一（没有闪光点）**：作者包里有**两个空闲变体**——

| 组 | 时长 | 内容 |
|---|---|---|
| `Idle` | 9.0s | 安静坐姿（呼吸、眨眼、小幅姿态） |
| `Idle#1` | 16.0s | **风起、花瓣飘落、发光星点/闪光点**、抬手 |

Live2DViewerEX 里这两个是**轮着播**的；我们壳里只播 `Idle` 组那一支 → `Idle#1` 的内容永远不出现，所以看不到闪光点。

**根因二（循环不流畅）**：包里 motion3 **全被标成 `Loop: true`**，且两条空闲曲线的首尾值不连续：`Idle` 最差 **69.5°**（头发旋转）、`Idle#1` 最差 **610 单位**（物件大小/角度那组 `MB_*wuti*`）→ 每循环一次硬跳回开头（`Idle#1` 那条尤其明显）。

**做法**（`_patch_pack2.py` 改 zip + `_patch_idle_cycle.py` 改壳）：
1. 只让两个空闲变体保持 `Loop: true`，**其余 32 个动作一律 `Loop: false`**（播完自己回待机，不再死循环）；
2. 两个空闲变体做**末端收敛**（方案 C：`v'=(1-α)v+α·v0`，`α=smoothstep`，`W=min(2.5s, 35%·D)`，只改窗口内已有关键点 + 在 D 处钉一个点）；
3. 壳里加**空闲变体轮播**：`albion:motion-finish` 里在两个变体间切换（并允许 `Idle#1`；刚播完的是哪组优先问引擎，自己记的那份会过时）。

**实测验收**：
- 收敛：`Idle` 首尾差 `69.532 → 0.00e+00`、`Idle#1` `610.000 → 0.00e+00`；zip 19,364,719 → 19,203,734 字节（备份 `albion.zip.bak-seam2`）
- 轮播：连续观察 82 秒，动作序列 `Idle#1 → Idle → Idle#1 → Idle → Idle#1 → Idle → Idle#1 → Idle`（时长分别 ≈9s/≈16s，与 Meta 一致）
- 回归：点她的头 → `Touch_head.body.special`（≈9s）→ `Idle` → `Idle#1` → 回 `Idle`，触摸链没被打断
- 平滑：录 30 秒（2952 帧）按真实时间戳编码，10fps 采样做相邻帧差 —— 中位 2.95 / p99 4.32 / 最大 4.56 → **max÷p99 = 1.06**（旧模型修前是 1.6+ 的 9 秒周期尖峰）
- 闪光点：`Idle#1` 中截图确认「发光星点 + 飘落花瓣 + 被吹起的头发/衣摆」都在窗口内完整可见
- 交付物：`_空闲_轮播_修后.mp4`（30s 实拍）、`_idle_cycle_1.png`

### 9.8 找到引擎源码：方向键的用意 + 按要求做无缝衔接（2026-09-16）

**指挥官指的那份 GitHub 是源码** ✓ —— `github.com/Sosarciel/Live2dViewerEX`（作者 zwa73，包名 `@sosarciel-live2dviewerex/live2dviewerex`）。它是**解释 `model0.json` 的那个引擎**（不是闭源的桌面 App 本体，但语义全在这里，比看 App 更直接）。

**① 方向键（手柄）作者的用意** —— 看 `src/Live2D/Controllers.ts` 的 `ParamHit` 类型：

```
Items: { Name, Id, HitArea,
  Axis: 0|1,            // 坐标轴 X / Y
  Factor: number,       // 因子
  ReleaseType,          // 释放：0 线性 1 缓出 2 快出 3 缓入缓出 ← 是**缓动曲线**，不是我以前理解的"保留/弹回"
  MinMtn, MaxMtn }      // 参数拖到最小/最大时播的动作
```

作者给 `手柄` 这块区域配了**四条**参数：

| 条目 | 参数 | 轴 | LockParam |
|---|---|---|---|
| 视角-左右 | `touch_drag9` | X | ✓（松手保持）|
| 视角-上下 | `touch_drag10` | Y | ✓ |
| 手柄-左右 | `touch_drag11` | X | ✗（松手回弹）|
| 手柄-上下 | `touch_drag12` | Y | ✗ |

也就是：**一个摇杆同时驱动"视角"和"手柄本身"两组 X/Y** —— 横拖动两条 X、竖拖动两条 Y、斜拖四条一起动。以前我的实现一次只挂一条参数，所以只动得了一个方向 —— 已改成**同一块命中区上的参数全部一起拖**（`beginDrag` 按 `HitArea` 收集，`applyDrag` 按每条自己的轴取位移）。`MinMtn/MaxMtn`（拖到极限播动作）引擎支持，但这个包没填，所以不用接。

**② 无缝衔接：引擎里作者的做法**（`src/ModelFramework/*` + `src/Live2D/Motion.ts`）

- **`PreMtn`（提前运行的动作）** —— 注释原文写着"前置动作指令 使用前置指令是唯一打断 idle 动作的方式"：下一跳在**这一条结束之前**就开始，交叠着淡入。
- **`FadeIn` / `FadeOut`** 是每条动作自己的字段（作者这个包没填 → 引擎用默认；我们按"无缝"给了值）。
- **层级直接写在组名里**：`name#层号`（引擎里 `ControlLayer = 99`、`UpdateLayer = 98`），不同层级**同时播**、高层级覆盖同名参数 —— 这就是 `Idle` + `Idle#1(effect)` 的正确关系，也印证了上一轮"离线合成两层"的方向。
- `ReleaseType` 是缓动（见上），**不是**"保留/弹回"；回不回弹看 `LockParam`。

**这一轮改了什么**：
1. `albion.model3.json` 给每条动作写上 `FadeInTime`/`FadeOutTime` —— 一次性动作 **0.35s**、待机 **0.6s**（以前是空值/旧值，交界处是硬切）。
2. 壳里加**提前接力**（作者 `PreMtn` 的做法）：动作播到 `时长 - 淡出` 就把下一条接上（`NextMtn` 那条；作者标了 `FileLoop` 的姿势 idle 就提前重播自己），不再等播完再切 —— 这就是"停顿"的来源。
3. 摇杆四条参数一起拖（见 ①）。

**实测**：

### 9.9 两处"不流畅"的根因：淡入淡出写错了地方 + 循环根本没开（2026-09-16）

### 9.10 收尾两处：场景动作"停在最后一帧" + 待机 2→1 的回摆交给淡入（2026-09-16）

### 9.15 事故：分层驱动把壳搞崩（2026-09-17）

**现象**：加了"循环窗口 + 接缝交叉淡入"之后，壳的 CDP 页面 evaluate / 截图都返回内部错误，`127.0.0.1:5173` 也连不上 —— 渲染进程死了、Vite dev server 也没了。

- 时间严格夹在 `[begin, stop)` 内并且 `Number.isFinite` 检查，SDK 永远拿不到负数/越界值；
- 单层动作（触摸链）不插手；层 0 与层 1 都按窗口推进（pixi 自己的 9s/16s 循环被覆盖）。
