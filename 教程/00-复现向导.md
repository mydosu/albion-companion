# 00 复现向导

这份向导写给两类读者：想自己动手搭一套 AI 桌宠的人，以及替人执行搭建任务的 coding agent。人看的详细原理和踩坑笔记在各篇[教程](README.md)，本篇是端到端执行清单：按阶段顺序推进，每阶段明确「这一步在干嘛 → 前置 → 操作 → 验收」。

### 这套桌宠是什么

这不是一个打包好的单一现成软件，而是一套各司其职、协同运行的桌面陪伴系统。整套系统主要包含这几个核心部件：
- **壳**（桌面外壳）：基于 Electron 构建的透明窗口应用，在屏幕上渲染 Live2D 或 Spine 3.8 角色模型（两种 2D 骨骼动画格式，把切片立绘拼成可动作的角色），并承载聊天气泡与交互界面；
- **脑**（Pi 宿主）：运行在 WSL 环境里的智能体框架（Pi，基于 Node.js 开发的智能体宿主），接入大语言模型，负责理解输入、调度工具、维护状态并决定何时主动开口；
- **声音**（TTS 语音管线）：Irodori-TTS 语音合成后端 + 翻译桥 + 流式切句网关，负责把脑生成的中文回复翻译成日文，并用角色的音色流式念出来；
- **耳朵**（ASR 语音输入）：基于 paraformer 的本地离线语音识别服务，把麦克风里的说话声实时转成文字喂给脑，且能自动防回音、不抢话；
- **记忆**（OpenViking 长期记忆服务）：把平时的真实对话提炼并沉淀在本地，并在隔天或跨场景聊天时按需主动召回；
- **眼睛**（采集端与本地视觉模型）：负责定时或按需截取本机与主力机的屏幕，并通过局域网视觉模型分析摄像头画面；
- **挂件**（状态小摆件）：桌面边缘常驻的半透明毛玻璃悬浮卡片，实时刷新她刚调用的工具、查看的文件、当下的心情与今日对话数。

按向导做完之后，桌面上会跑起一个桌宠：显示角色立绘与动作，能打字也能语音聊天，用角色的声线念出回复，能看屏幕和摄像头，隔天保留之前的对话记忆，并在特定时间主动发消息找你。

阶段 1–10 对应教程 01–10。路径、端口、角色名沿用参考部署；你的环境不同时，按各阶段标出的「改这里」逐处替换。如果是由 agent 替你执行，卡住时把命令、输出、日志末尾 30 行报给人。

## 执行约定（人与 agent 共通）

1. 按阶段顺序做，不跳阶段。标「可选」的阶段，人明确说不要才跳。
2. 每阶段开始前核对「前置」是否满足；做完立刻跑「验收」。验收不过，停下，把命令、输出、日志末尾 30 行报给人。不猜，不绕过，不降级验收标准。
3. 下表的东西只能由人提供。用到时停下问人，不要自己编、不要去网上找替代品。
4. 密钥、token、人设、聊天数据只写进不入库的文件（`.env.local`、`agent/.env`、`agent/models.json`、`eyes/token.txt`、`ov.conf`）。不在命令行、日志、提交、回复里出现密钥明文。
5. 不 force push，不改写历史，不 `git add -f` 私密或备份目录；提交前跑 `python tools/check_repository.py`。
6. 每个阶段凡是有自动化脚本的，先跑脚本，再按验收检查；手工步骤留着当退路。命令只用本向导、`tools/setup/README.md` 和 `docs/REBUILD.md` 里已有的。
7. 路径是参考部署的：仓库根 `D:\AI\Wife`，WSL 脑 `/root/albion-pi`，记忆服务 `D:\AI\openviking`。要换路径，先搜这些路径的斜杠和反斜杠写法，逐处改并验证（见 `docs/REBUILD.md`「克隆与选择版本」）。第一次复现建议原样用这几个路径。
8. 在 Windows 上拉起常驻服务，用仓库的 `launch/silent_run.ps1`（和 `launch/start_all.bat` 同一套），别用 `start /min` 或自写包装 bat，免得桌面弹一堆控制台、也免得服务随会话结束。

| 项 | 建议 | 依据 |
|---|---|---|

## 阶段 0 环境准备

**这一步在干嘛**：安装整套系统需要的 Windows 基础工具链、显卡驱动、WSL2 子系统与环境管理器，并把代码仓库完整拉到本机。
**做完能看到什么**：各服务所需的底层命令与解释器全部就位，仓库自检退出码为 0，没有缺失环境报错。

**目标**：工具链齐全，仓库克隆到位，布局门禁通过。

**前置**：Windows 11，管理员权限可用，能访问 GitHub、npm、PyPI、Hugging Face、ModelScope。

**需要人提供**：Tailscale 账号（可选，仅阶段 9 跨机用）；GitHub 登录（`gh auth login` 由人完成，不要把 token 写进命令或 URL）。

**操作**：

| 项 | 版本 | 说明 |
|---|---|---|
| WSL2 + Ubuntu | 发行版名 `Ubuntu` | 脑的启停脚本里写死 `wsl -d Ubuntu`。`%USERPROFILE%\.wslconfig` 里 `[wsl2]` 下写 `networkingMode=mirrored`，改完 `wsl --shutdown` 重进。Windows 要能用 `127.0.0.1:8650` 访问 WSL 里的脑，靠的就是 mirrored。**WSL 默认用户要是 root**：脑住 `/root/albion-pi`，启动器调 `wsl -d Ubuntu -- bash /root/albion-pi/start.sh` 不带 `-u`；新装的 Ubuntu 默认是你建的普通用户，在 WSL 的 `/etc/wsl.conf` 里写 `[user]` 下一行 `default=root`，再 `wsl --shutdown` |
| Git、GitHub CLI | 当前版 | `gh auth status` 能通过 |
| Python（Windows 系统） | 3.13 | 挂件启动器（`AlbionStatus.vbs`）默认先找 PATH 里的 `pythonw.exe`/`pyw.exe`/`py.exe`，再退回 `%LOCALAPPDATA%\Programs\Python\Python313\pythonw.exe`，可以用环境变量 `ALBION_PYTHONW` 覆盖；`tools/`、`tests/` 的标准库脚本用它跑 |
| uv | 当前版 | 阶段 4 建 TTS 环境用（Python 包和环境管理工具） |
| Node + pnpm（Windows） | 以 `docs/REBUILD.md`「桌面壳」为准：参考机器 Node `22.23.2`、pnpm `10.32.1`；`shell/package.json` 声明 `pnpm@11.24.0` | 以 lockfile 为准，不要盲改 |
| Godot .NET 版 + .NET SDK | Godot 4.7.1 .NET 版、同版本 .NET 导出模板、.NET 10 SDK | 阶段 2 构建壳时导出 Godot 舞台用，缺了构建在 beforePack 失败；见 `docs/GODOT_SIDECAR.md` |

### 本机配置：config/local.env

Windows 侧各服务的配置统一写在 `config/local.env`。从模板复制一份：

```powershell
Copy-Item config\local.env.example config\local.env
```

规则：
- 一行一个 `KEY=VALUE`，空行忽略，`#` 开头是注释，值不要加引号。
- 真环境变量优先（同名环境变量不会被覆盖，临时调试可在当前窗口 `set` 压过配置）；每个服务的启动 bat 在拉起时都会通过 `launch/load_env.bat` 自动读它。
- 配置分组（照 `config/local.env.example`）：
  - **通用**：静默运行与控制台窗口可见性（`ALBION_SILENT`、`ALBION_SHOW_CONSOLES`）；
  - **TTS 引擎与设备**：TTS 后端二选一（`ALBION_TTS_ENGINE=irodori|gsv`，默认 irodori）、GSV 设备（`ALBION_GSV_DEVICE=cuda|cpu`，默认 cuda）；
  - **TTS 资产位置**：参考音目录、GSV 安装目录、Denia 参考音与端口、Irodori 桥目录；
  - **声音后端正本（Irodori）**：原文日志记录与受控声音字幕（`TTS_LOG_TEXT`、`ALBION_VOICE_CAPTION`）；
  - **声音桥**：翻译线路、协议形态、模型与 Codex CLI 路径等。**特别点明**：TTS 翻译退路的 key 文件路径 `TTS_TRANSLATE_KEY_FILE` 必须写在这里，指向你本地存放密钥的文件，否则主路不可达时翻译退路会断；
  - **流式语音网关**：切句计划器版本、句间停顿整形、情感融合策略等；
  - **耳朵（STT）**：引擎选择（paraformer/whisper）、端口、设备与模型目录；
  - **眼睛（采集端）**：ffmpeg 路径、摄像头名称与画面顺时针旋转角度；
  - **挂件**：指定 Python 解释器路径（`ALBION_PYTHONW`，备用记录）。

## 阶段 1 找角色模型（教程 [01](01-找到角色模型.md)）

**这一步在干嘛**：准备好角色的 Live2D 或 Spine 动画切片模型包，核对格式版本与互动数据，放到外壳引用的指定目录。
**做完能看到什么**：两个模型压缩包已放入 assets 对应文件夹，权重恢复脚本能校验到文件存在（此时桌面上还没有窗口界面）。

**目标**：本机有一份能用的 Live2D（Cubism 4，`.moc3` + `model3.json`）或 Spine 3.8 模型，且已核对里面有你想要的部件和交互数据。

**前置**：阶段 0。

**需要人提供**：模型文件本身；解包得来的话，解包工具和合法来源由人负责。

**操作**：

1. 让人给出模型；按教程 01 的「拿到之后先检查这几项」逐项核对：格式版本、模型里有什么、有没有交互数据（`model0.json` / `modelN.json`）、画布形状。
2. 放置（参考路径，文件名来自 `config/rebuild/assets.json` 的 `local_assets`）：

| 位置 | 内容 |
|---|---|
| `shell/packages/stage-ui/src/assets/live2d/models/albion.zip` | Live2D 包 |
| `shell/packages/stage-ui/src/assets/spine/models/albion-spine-38.zip` | Spine 3.8 包 |

   这两个路径被壳源码按名字引用（`shell/packages/stage-ui/src/stores/display-models.ts`、`shell/packages/stage-ui/src/albion/albion-pet.ts`）。第一次复现沿用这两个文件名。换角色要搜这两处引用。
3. 模型不入库（`.gitignore` 已忽略 `*.zip`）。

**验收**：

| 命令 | 期望 |
|---|---|
| `Get-Item shell\packages\stage-ui\src\assets\spine\models\albion-spine-38.zip` 及 live2d 那份 | 文件存在（至少有你要用的那一条链路） |
| `python tools/restore_weights.py` | 对应两个包不再出现 `EXTERNAL_MISSING`。换成自己的模型会报 `EXTERNAL_HASH_MISMATCH`，属正常：该脚本的哈希只匹配参考权重；整套权重齐之前退出码非 0 也正常 |

## 阶段 2 构建桌面壳（教程 [02](02-改壳适配模型.md)）

**这一步在干嘛**：配置基础连接参数，使用 pnpm 编译打包出基于 Electron 的桌面透明外壳应用 `airi.exe`，并完成首次启动与调试端口验证。
**做完能看到什么**：桌面上会出现一个透明角色窗口，待机动作在播放，点击身体和头部有反应；此时脑还没启动，她还不会出声说话。

**目标**：`airi.exe` 构建出来，打开后角色显示、能动。

**前置**：阶段 0、1。

## 阶段 4 训练角色声音（教程 [04](04-训练角色声音.md)）

TTS 后端支持二选一：默认是 Irodori（:9889，日语特化），中文角色可选 GSV（:9880，Denia），在 `config/local.env` 中设 `ALBION_TTS_ENGINE=irodori`（默认）或 `gsv`；两者对比和选型参见教程 04 [「先选引擎：Irodori 还是 GSV」](04-训练角色声音.md#先选引擎irodori-还是-gsv)。本阶段以默认的 Irodori 路线为主，走 GSV 的见 [tts/gsv/README.md](../tts/gsv/README.md)。

**这一步在干嘛**：搭建 TTS 运行环境，基于角色原声训练声音权重（LoRA 与说话人嵌入），启动语音合成后端与日中翻译桥服务。
**做完能看到什么**：向桥服务发送一段台词，能生成 WAV 音频文件；听起来是角色的声线。

**目标**：Irodori 后端（:9889）和翻译桥（:9881）跑起来，她的中文回复用角色声音念出来。

**前置**：阶段 0；阶段 3（桥的翻译首腿问脑要用 `:8650/health`）。

**需要人提供**：

| 东西 | 去处 |
|---|---|
| 角色原声音频 + 官方原文，一一对应 | 数据整理见操作 2 |
| Irodori 底模 `model.safetensors` | `tts/irodori/checkpoints/model.safetensors`；参考基线大小 3,064,295,596 字节，哈希在 `config/rebuild/assets.json`。从 Hugging Face `Aratako/Irodori-TTS-v4.1-Small` 取；哈希对不上时停下问人，别自行替换 |
| 参考音频 | `tts/ref_audio/<角色>/`，后端优先找 `004.wav`、`068.wav`、`072.wav`、`003.wav` |
| 翻译用的模型 key | 见操作 5 |
| 自训权重 | 按操作 3 自己训 |

**操作**：

1. 建 TTS 环境：先跑自动化脚本建 `tts/irodori/.venv`（支持 `-DryRun`，说明见 [tools/setup/README.md](../tools/setup/README.md)）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup/setup_tts_env.ps1
```

   （也可以通过 `.\一键安装.bat -Only tts` 运行）。脚本会自动检查 uv 与显卡驱动，调用 `uv sync --frozen --extra cu128 --python 3.10` 并安装服务层依赖。手工步骤留作退路：手动在 `tts/irodori` 执行 `uv sync --frozen --extra cu128 --python 3.10` 并用 pip 安装 fastapi、uvicorn、httpx、websockets。50 系以外显卡先确认 CUDA 版本与驱动匹配。
2. 数据整理：可以使用 `tools/voice_data/build_dataset.py` 将音频目录 + 台词表（csv/json：`file,text[,start,end]`）整理成 Hugging Face `audiofolder` 数据集（`train/*.wav` + `metadata.csv`），只用标准库（非 wav 走 PATH 里的 ffmpeg，自检命令 `python -I tools/voice_data/build_dataset.py --selftest`，详见 [tools/voice_data/README.md](../tools/voice_data/README.md)）；手工抓取与对齐留作退路（教程 04「① 数据」）。整理完在 `tts/irodori` 目录用 `prepare_manifest.py` 编码成 latent 清单（latent 即潜空间特征表征，指音频提取压缩后的特征向量）：

```bash
uv run --no-sync python prepare_manifest.py \
  --dataset audiofolder \
  --data-files "train=<out>/train/*" \
  --split train \
  --audio-column audio \
  --text-column text \
  --output-manifest data/albion_manifest.jsonl \
  --latent-dir data/albion_latents \
  --device cuda
```

3. 训练（命令照抄 `tts/irodori/README.md` 的 Training 一节；配置用 `tts/irodori/configs/train_v4_small_lora.yaml` 和 `train_v4_small_speaker_inversion.yaml`）。**训练前先关 TTS 后端**，显存放不下两个。在 `tts/irodori` 目录运行：
   - LoRA 训练（照抄 `tts/irodori/README.md`「Training → 3. LoRA Fine-Tuning」）：

```bash
uv run --no-sync python train.py \
  --config configs/train_v4_small_lora.yaml \
  --manifest data/albion_manifest.jsonl \
  --output-dir outputs/albion_lora \
  --init-checkpoint checkpoints/model.safetensors
```

     改 yaml 的 `train:` 段，数据几十条时 `max_steps` 200 起步、`save_every` 100，听完再挑检查点；warmup 步数别大于 max_steps（教程 04 的坑：warmup 1000 = max_steps 时最终那份退化）。其余参数用 yaml 默认值、对照教程 04 的表。产物落点：`tts/irodori/outputs/<训练名>/checkpoint_<步骤>/adapter_model.safetensors` + 同目录 `adapter_config.json`。
   - 说话人嵌入（照抄 `tts/irodori/README.md`「Training → 4. Speaker Inversion」）：

```bash
uv run --no-sync python train.py \
  --config configs/train_v4_small_speaker_inversion.yaml \
  --manifest data/albion_manifest.jsonl \
  --output-dir outputs/albion_inv \
  --init-checkpoint checkpoints/model.safetensors
```

     步数等参数同上，按教程 04 的表。产物落点：`tts/irodori/outputs/<训练名>/checkpoint_<步骤>.speaker.safetensors`（后端找 `checkpoint_0000500.speaker.safetensors`，找不到取目录下最后一个）。

4. 把训练名写进 `tts/irodori/ships.json`（改完自动生效，不用重启）：`lora` 填 outputs 下 LoRA 目录名，`inv` 填嵌入目录名（`null` 则按 `<ship>_inv` 约定找，例如配置 `"albion": {"lora": "albion_lora", "inv": null}` 会自动对应 `outputs/albion_lora` 与 `outputs/albion_inv`）。**目录名写错不会报错，只是不生效。** 该文件里另有参考部署的其他角色条目，第一次复现只保留 `albion` 一条即可。
   - 换角色名：设环境变量 `TTS_DEFAULT_VOICE=<新名>`（默认 `albion`），`bridge.py`、`irodori_serve.py`、`render_queue.py` 的默认音色随之变化，桥的 `VOICES` 自动收录该名；在 `tts/irodori/ships.json` 加上同名条目即可，热载不用重启（详见 [tools/voice_data/README.md](../tools/voice_data/README.md)）。沿用 `albion` 则不用动。
5. 翻译：桥支持通用的 OpenAI 兼容接口。若使用独立线路，设 `TTS_TRANSLATE_BACKEND=api` + `TTS_TRANSLATE_API_STYLE=chat`，配合 `TTS_TRANSLATE_BASE`、`TTS_TRANSLATE_MODEL`、`TTS_TRANSLATE_KEY`（打标准 `/chat/completions` 接口，自检命令 `python -I tests/tts/test_translate_api_chat.py`）。注意：纯外部线路请再设 `TTS_BRAIN_ROUTE=0` 关闭向脑探路。不设 `TTS_TRANSLATE_API_STYLE` 时默认按历史 Responses API 处理。这些配置项写进 `config/local.env`（模板 `config/local.env.example`），`launch/load_env.bat` 会在每个服务启动 bat 开头自动加载，真环境变量优先。
6. 启动（先后端，等约 15 秒，再桥）：

```powershell
New-Item -ItemType Directory -Path D:\AI\Wife\logs -Force
powershell -NoProfile -ExecutionPolicy Bypass -File D:\AI\Wife\launch\silent_run.ps1 -Bat D:\AI\Wife\tts\irodori\start_backend.bat -Log D:\AI\Wife\logs\irodori.log
powershell -NoProfile -ExecutionPolicy Bypass -File D:\AI\Wife\launch\silent_run.ps1 -Bat D:\AI\Wife\tts\irodori\start_bridge.bat -Log D:\AI\Wife\logs\tts_bridge.log
```

**验收**：

| 命令 | 期望 |
|---|---|
| `Test-NetConnection 127.0.0.1 -Port 9889` | `TcpTestSucceeded : True` |
| `curl.exe -s http://127.0.0.1:9881/v1/models` | 200，列出音色（含你的角色名） |

## 阶段 9 她的眼睛（教程 [09](09-她的眼睛.md)）　可选

**这一步在干嘛**：启动屏幕采集服务（带密码框和敏感词涂黑），并在局域网视觉机上运行本地视觉模型，供摄像头这一路使用。
**做完能看到什么**：对她说「看下我的屏幕」或「看下摄像头」，她能说出屏幕上开着什么、摄像头前有没有人，且命中规则的敏感窗口会被涂黑。

**目标**：她能看自己那台的屏幕（`mine`）、你主力机的屏幕（`his`）、摄像头（`cam`，只经本地视觉模型转文字）。

**前置**：阶段 3。分三块，可以只做前两块：本机采集端、主力机采集端（跨机，需要第二台电脑，可选）、本地视觉模型（摄像头用，可选）。

**需要人提供**：第二台电脑与 Tailscale 账号；视觉机；`token.txt` 的值由 agent 现生成，不用人给，但不能入库。

**操作**：

1. 本机采集端：在 `eyes/` 建 `token.txt`，**只写一行 token**，让 Python 写文件，别用 `>`（PowerShell 5 会写成 UTF-16）：

```powershell
python -c "import secrets, pathlib; pathlib.Path('eyes/token.txt').write_text(secrets.token_urlsafe(18))"
```

   缺文件或为空时采集端直接不起。`start_all.bat` 第 5 步用它以 `--bind 127.0.0.1` 拉起 :8790；也可以手动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\AI\Wife\launch\silent_run.ps1 -Bat D:\AI\Wife\eyes\start_eyes.bat -Log D:\AI\Wife\logs\eyes.out.log
```

2. 主力机采集端（跨机）：把 `eyes/` 放到主力机，建它自己的 `token.txt`，双击 `启动采集端.bat`（带 `--lan`：除 Tailscale 地址外再绑 10/8、192.168/16 的局域网地址；首次防火墙询问选「专用网络」）。主力机上要装 Python 和 Tailscale。
3. 脑的 `agent/.env` 追加（每次调用现读，不用重启）：`ALBION_EYES_MINE_URL`、`ALBION_EYES_MINE_TOKEN`（本机）；`ALBION_EYES_HIS_URL`、`ALBION_EYES_HIS_TOKEN`（主力机；URL 可写多个、逗号分隔，局域网在前、Tailscale 在后，地址用 `<主力机 Tailscale IP>` 这类占位替换成真实值）；`ALBION_EYES_VLM`（视觉模型地址）。
4. 摄像头：采集端用 ffmpeg 走 DirectShow（Windows 系统的多媒体采集接口）。默认值均为作者机器的配置，换设备可以用环境变量覆盖，不用改代码：
   - ffmpeg 路径：默认值是 `D:/ffmpeg-2026-03-22-git-9c63742425-full_build/bin/ffmpeg.exe`（不存在时自动退回 PATH 里的 `ffmpeg`），可以用环境变量 `ALBION_FFMPEG` 改；
   - 摄像头名：默认值是 `FHD Camera`，可以用环境变量 `ALBION_CAM` 改；
   - 顺时针旋转角度：默认值是 `90`（只接受 0/90/180/270），可以用环境变量 `ALBION_CAM_ROTATE` 改（也可以用命令行参数 `--cam-rotate`）。
5. 视觉机：仓库提供了完整的部署包 [eyes/vision-server/](../eyes/vision-server/README.md)（用 docker compose 起 llama.cpp 加 Qwen3-VL 4B，带模型下载与防火墙脚本）。在视觉机上（Linux + NVIDIA 驱动 + Docker Compose + nvidia-container-toolkit）：

```bash
git clone <本仓库> && cd <本仓库>/eyes/vision-server   # 或将 eyes/vision-server/ 目录拷贝到视觉机
cp .env.example .env                             # 确认 .env 里的 MODEL_FILE / MMPROJ_FILE / MODEL_DIR
bash download_models.sh                          # 下载 Qwen3-VL 4B GGUF 与 mmproj
sudo bash firewall.sh install                    # 配置 DOCKER-USER 链（Docker 在 iptables 里的自定义过滤链），只放行局域网和 tailnet
docker compose up -d
docker compose logs -f --tail 50                 # 确认 "server is listening"
```

   通用 `docker run` 单命令起法留作退路（命令见 [eyes/vision-server/README.md](../eyes/vision-server/README.md)）。防火墙只放行局域网和 tailnet。地址填进 `shell/apps/stage-tamagotchi/.env.local` 的 `VITE_ALBION_VISION_BASE`（要重新打包）和脑的 `agent/.env` 的 `ALBION_EYES_VLM`；`curl.exe -s http://<视觉机 IP>:8080/health` 返回 200 即可用。
