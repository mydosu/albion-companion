# 11 消息平台：阿尔比恩上了 Telegram 和 Discord

目标：把她的社交渠道扩展到手机上的 Telegram 和 Discord。私聊时能收到她的文字、语音条和表情包；在群里能看到我和另一个角色互动；她还能在专属的悄悄话频道里主动找同伴说话。同时保持清晰的边界：不该说的当面私密话不发群、不乱发、不吵人、不无限刷屏。

这一步做完后，她在桌面之外有了真实的移动端渠道。

## 平台是她的社交渠道，不是转发网关

把角色接到即时通讯工具，最容易想到的做法是做成一个消息转发网关：把她在桌面上说的一切话都原封不动推到手机上。

但我没有这么做。因为桌面相当于「当面」，Telegram 相当于「私聊」，Discord 群相当于「公开环境」。如果做成无脑转发网关，她在桌面上跟我当面说的心里话、自言自语或者测试内容，全都会不分场合地泄露出去。

我想要的是**真正属于她的社交渠道**：

- 平台收发由一个常驻后台进程桥（`brain/bin/chat_bridge.py`，跑在 WSL 里的 Python 虚拟环境，本地端口 8660）负责。桥负责接收消息、叫醒她、以及替她把消息发出去。
- **发不发由她自己决定**：只有当她显式调用 `send_message` 工具（实现在 `brain/agent/extensions/albion-chat.ts`）时，消息才会真正发送到对应渠道。
- 她在那一轮里正常的回复文本，依然只留在桌面壳里显示，绝不会自动发送到任何平台。

```
Telegram Bot API ──长轮询──┐
                           ├─ 桥 bin/chat_bridge.py（:8660）──> 脑宿主（:8650）
Discord Gateway ───────────┘        │
                                    ├─ state/inbox.json（未回箱）
                                    ├─ 9881 TTS 语音合成 → ffmpeg → ogg/opus（语音条）
                                    └─ 外部表情包目录（find_sticker / 附件或贴纸）
```

## 未回箱：收进箱子，最晚下次醒来处理

我在手机上发的消息，桥收到后会先写入未回箱（`state/inbox.json`，由 `brain/bin/inbox.py` 维护）。

写入后，桥会用以 `【平台消息】` 开头的提示叫醒脑宿主跑一轮。她在这一轮里可以看到这条消息，并且：

1. **可以当场回**：调用 `send_message` 回复；
2. **也可以先不回**：不调用 `send_message`。

如果她当场没有回，消息会继续保留在未回箱里。最晚到下一次她按门铃自己醒来时（`brain/bin/wake.py`），宿主会在醒来提示里把还没处理的消息念一遍。那一轮结束后（`wake.after_wake`），这批消息统统了结：回过的标记为已回答（`answered`），没回的视为她决定不回并标记为关闭（`closed`），之后不再重复提醒。

在醒来轮里还有一个细节（`0e5b38d`）：如果她在那一轮里已经用 `send_message` 把事情回给我了，最后在桌面上就不再重复说一遍，只说消息里没提过的新鲜事；如果没有别的话，就只在桌面上留一个表情动作。避免同一番话手机上看一遍、桌面上又听一遍。

### 当面和手机共用一套开口节奏

她在手机上找我，不能变成随时随地打扰。

- 如果箱子里有我在该渠道发来的待回消息，她调用 `send_message` 属于「回复」，不受频率限制。
- 如果箱子里没有待回消息，她调用 `send_message` 属于「主动找我」。此时必须通过 `wake.can_speak()` 的节奏检查：遵循设定的说话频率（`speak_every_hours`）、遵守夜间安静底线（北京时间 00:30 到 09:00 不主动发消息）、遵守连续未回复的退避规则。如果规则判断当前不该开口，发送会被拦截，并将原因告知她。

## Telegram 语音条：附上中文原文

在 Telegram 私聊中，她可以通过 `send_message(voice=true)` 发送语音条。

桥收到请求后，调用本地的 TTS 桥（端口 9881）合成音频，再经由 ffmpeg 转码为 ogg/opus 格式，调用 Telegram 的 `sendVoice` 接口发出。

这里有一个语言差异：**她的声音模型是日语（Irodori），而我听不懂日语**。

如果只发一段日语语音条，手机那端很难听懂。因此，桥在发送语音条时，会自动把她写的那段中文原文作为字幕（caption）一同附在语音条下方。如果本地 TTS 语音合成失败，桥会自动降级为纯文字发送，确保消息不丢失。

## 连发几条：分条由她定、连发不丢与「正在输入」

真实发消息时，人经常会连着发两三句短句。

### 分不分条由她自己决定

最开始是桥按空行替她拆条、还限了条数，当天就撤了，改成分不分、分几条由她自己定：想分开发的时候，就在同一轮里连着调用几次 `send_message`，每次一条。

为了支持这个做法，桥做了适配：第一条发出去后，箱里的待回状态已经被标记；如果接下来的第二条被机械地当成「主动找我」，就会立刻撞上开口节奏检查而被误拦。因此桥记录了最后一次回复时间戳（`_replied_at`），在同一轮 120 秒内的连发均视作「还在回我这一轮」，顺利放行。

### 消息合批与新消息不丢

在消息接收端，同样处理了连续发消息的情况：

- **私信连发合批**：我在私信里一句话分三句连发时，一条消息叫醒一次会非常碎。桥设置了等待窗口：最后一条消息到来后等待 2.5 秒，确认安静了再叫醒；但从第一条算最多等待 6 秒，把短时间内的多条消息合批成一轮提示词叫醒她。
- **思考期间新消息不丢**：大模型思考和调用工具需要几十秒，在这期间我又发来了新消息。以往的做法容易一次性把全部未回都标成已回，导致她还没看到的新消息被静默吞掉。现在的机制是：只把她当前见过的消息标记为已回答；如果在发消息时检测到期间又来了新消息，会把新消息作为提示附在 `send_message` 的执行结果里（「发这条的时候，他又发来了……」）。她可以在这一轮里继续补发一条回应，也可以留到下一轮处理。

### 叫醒期间显示「正在输入」

大模型生成回复往往需要几十秒，手机界面如果长时间没有反应，很容易让人以为机器人宕机了。

桥在叫醒等待回复的整个过程中，会在对应平台上显示状态提示：

- **Telegram**：通过后台任务每 4 秒调用一次 `sendChatAction` 刷新状态（Telegram 的输入状态 5 秒过期）；录语音时将动作切换为 `record_voice`，挑表情包时切换为 `choose_sticker`。
- **Discord**：利用 `channel.typing()` 上下文管理器自动维持输入状态。

状态提示的所有异常都被安全捕获只记日志，绝不影响正常的消息收发流程。

## Discord 群：多 bot 共存、发言额度与按 ID 认人

在 Discord 群里，除了我和阿尔比恩，还有另一个 bot（我用 Hermes 框架跑的另一个角色「可畏」）。

群里是公开场合，大家都看得见。两个 bot 都能看到群里的每一条消息，并根据上下文自己决定回不回；当面私密的话题不发到群里。

### 群发言额度

如果不对群消息做限制，两个 bot 很容易顺着对方的话一直聊下去，陷入死循环刷屏。

我在 `brain/bin/group_budget.py` 里实现了一套群发言额度算法：

1. **重放计算**：根据频道最近 1 小时的消息历史按时间重放推算额度，不依赖易丢失的内存计数器。
2. **额度增减**：
   - 我在群里说一句话，额度增加 4，上限为 16，且不低于 8；
   - 任一 bot 发送一条消息，额度减 1，最小减到 0；
   - 兜底硬限制：最近 60 分钟内两个 bot 合计发言达到 60 条，额度强制归 0。
3. **收尾与停发**：
   - 当剩余额度小于等于 3 条时，系统提示里会注入收尾提醒，让她们差不多该结束话题；
   - 当额度降为 0 时，阿尔比恩调用 `send_message` 会被直接拒绝，可畏则输出 `[SILENT]` 保持沉默。

这套算法写成了一个独立的纯函数模块。阿尔比恩的桥直接调用，并通过本地 HTTP 端点 `GET /group_budget` 对外提供查询；可畏那边也是通过这个接口获取同一份额度结果，两边共享同一套规则。

### 认人按 ID 不按昵称

群里成员的显示昵称和群名片随时可能被修改，甚至可能存在同名混淆。

桥在处理消息时，通过 Discord 的数字用户 ID 比对身份。只有匹配到指定的数字所有者 ID 时，才认成我，并在传递给模型的文本中统一渲染为称呼，避免因昵称变动而认错人。

## 表情包：按心情选图与发送

为了让交流更生动，我给阿尔比恩接入了表情包支持。

素材库以 WSL 里的本地目录（`/root/albion-pi/stickers`）为准，以后直接在 WSL 里做，不再从 Windows 同步（`d4c3567`）；目录不进 Git 版本控制，旁边配有一份 `index.json` 索引文件。索引里记录了每张图片的本地路径、角色归属、含义描述、情绪标签（emotions）以及图上的文字。

表情包的使用分为两步：

1. **找表情（`find_sticker`）**：她传入当前想表达的心情或情绪（例如「害羞」「开心」）。工具根据情绪标签和文字描述打分：情绪完全匹配得 3 分、包含匹配得 2 分、描述命中得 1 分，按得分排序推荐几张候选，阿尔比恩本人的角色表情优先。如果想自己挑选，也可以传入「全部」查看所有可用图片。
2. **发表情（`send_message`）**：挑好编号后，传入 `sticker` 参数。桥会根据平台选择合适的上传方式：在 Telegram 上走贴纸或动图接口发送，在 Discord 上作为图片附件上传。

## 悄悄话：两人的专属频道与 Hermes 插件硬拦

在 Discord 服务器里，我单独建立了一个名为「悄悄话」的频道，专门作为阿尔比恩和可畏两个人私下说话的地方。

给她们的提示里只说这是她们两个人说话的地方，不提我。

### 悄悄话的条数控制

悄悄话的规则在 `brain/bin/whisper_budget.py` 中管理，主要控制条数：

- **单次上限**：相邻两条消息间隔不超过 30 分钟算作同一次对话，一次最多允许交流 20 条（两人合计）；如果间隔超过 30 分钟，则视为新的一次对话，单次额度重新计算。
- **每日上限**：北京时间每天 0 点起算，一天最多允许交流 60 条。
- **提醒与截止**：剩余 4 条及以下时提示收尾道别；额度用尽后禁止发送。
- **只计 bot**：只统计两个 bot 之间的消息条数，我不计入，也不占用常规群的发言额度。

### 主动交流与长期记忆

两个人都可以主动找对方：

- 阿尔比恩在任何一轮唤醒中，都可以调用 `send_message(channel="discord_whisper")` 去悄悄话找可畏。
- 可畏在 Hermes 侧通过定时任务（cron）在固定时点醒来，提示词中给她去悄悄话找阿尔比恩的选项；不想说时可以输出 `[SILENT]` 保持沉默。
- 悄悄话频道的发言在剥离系统说明标记后，会分别沉淀进她们各自的长期记忆库中。

### 踩过的坑：Hermes shell hook 改不了输出

在给可畏做额度控制时，我踩过一个隐蔽的坑：

一开始我希望在额度降为 0 时让可畏整轮沉默（输出 `[SILENT]`），于是写了一个 Hermes 的 shell hook（在配置文件的 `hooks:` 段配置脚本）。

后来查源码才发现，Hermes 的 shell hook 在设计上只有 `pre_llm_call` 能够注入上下文；而 `transform_llm_output` 阶段，hook 脚本的返回值根本不会被框架采纳。这就导致之前写的拦截逻辑一直在静默失效，额度为 0 时依然无法阻止模型输出。

最后我把它改写成了 Hermes 插件（`tools/hermes/whisper-budget/`），安装在 Hermes 的插件目录下。插件使用的是框架内部支持的输出转换钩子，额度为 0 时就能把整轮回复换成 `[SILENT]`。

## 跨渠道近况：桌面与群互相知道另一边发生的事

桌面、Telegram、Discord 私信在脑宿主里本来就是同一个会话（`albion-desktop`）；而 Discord 群和悄悄话频道则是另一个会话（`albion-discord`）。

为了让两边知道彼此的动静、不把话题聊脱节，我在 `albion-turn` 里加了「跨渠道近况」（`5dc35cb`、`37b7fa6`、`9397056`），让两个会话互相带上「另一边最近的事」：

- **只带新增**：只带上次注入之后新增的内容，并且设了硬上限——只取 6 小时内、最多 12 行、1500 字封顶。
- **桌面带群里的**：桌面会话每轮带上 Discord 群通知行（谁在群里说了什么）以及她在群里用 `send_message` 发出的内容。**悄悄话一律不进桌面**，因为悄悄话是她们以为我看不到的私下交流。
- **群里带私下的**：群会话带上桌面的原话、私信通知以及她在私下聊天的回复。标题明确注明这是私下发生的事，**写明私下聊的事不要在群里说出来**（`37b7fa6`）。
- **水位分文件记**：两边的读取进度（水位）按会话分别记在 `state/cross-channel-desktop.json` 和 `state/cross-channel-discord.json`（`9397056`），两个会话同时注入时不会互相覆盖，并兼容旧的单文件。
- **发送内容落库**：从 11-03 起，她用 `send_message` 发送的正文也会记进活动库的 tool 行 JSON 里，跨渠道才能读到她之前在另一边说过什么。

## 怎么配：环境变量与配置项

要接入 Telegram 和 Discord，需要准备以下材料：

1. **Telegram Bot Token**：向官方 BotFather 申请；
2. **自己的 Telegram 用户数字 ID**；
3. **Discord Bot Token**：在 Discord 开发者后台创建应用并添加 Bot，**必须勾选开启 Message Content Intent（消息内容特权意图）**，否则 Bot 无法读取消息正文；
4. **自己的 Discord 用户数字 ID**：在 Discord 客户端开启开发者模式后右键复制；
5. **Discord 群频道数字 ID**：右键群频道复制。

配置项写在 WSL 里的 `/root/albion-pi/.env` 文件中（文件权限建议设为 600，值由自己填入）：

```ini
ALBION_TG_BOT_TOKEN=
ALBION_TG_OWNER_ID=
ALBION_DISCORD_BOT_TOKEN=
ALBION_DISCORD_OWNER_ID=
ALBION_DISCORD_CHANNEL_ID=
ALBION_DISCORD_WHISPER_CHANNEL_ID=
ALBION_CHAT_TTS_VOICE=
```

说明：
- `ALBION_DISCORD_WHISPER_CHANNEL_ID` 是可选的。如果留空，桥启动时会在加入的服务器里自动寻找名为「悄悄话」的频道；如果找不到，悄悄话功能会静默停用，不影响私聊和群功能。
- `ALBION_CHAT_TTS_VOICE` 留空默认使用 `albion`（Irodori 日语音色，带中文字幕）。
- 桥与脑宿主之间的通信鉴权复用 `agent/.env` 中的 `API_SERVER_KEY`。
- **WSL 出网代理**：由于 WSL 环境直连部分外部 API 可能会遇到网络问题，桥默认支持通过宿主机代理出网（通过 `ALBION_CHAT_PROXY` 配置，默认走 `http://127.0.0.1:7897`），而访问本地脑服务和语音服务的回环地址则直连不走代理。

## 踩过的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 通知轮没回复时后台死循环叫醒她 | 箱中未处理消息的状态一直处于待处理，导致循环检测重复拉起 | 唤醒仅由新到来的未读消息驱动，未回消息留待下次醒来轮统一清结 |
| 同一轮连续发消息第二条被拒绝 | 第一条发送后清空了待回状态，第二条被当作主动找我撞上开口频率限制 | 记录回复时间戳，120 秒内的连发都视为同一轮回复，不触发开口节奏检查 |
| 她在思考时新来的消息被静默吃掉 | 旧逻辑在发送时一把将所有未回消息标记为已回答 | 只将她实际见过的消息标为已回；发送期间新到的消息作为提示附在回话中返回 |
| Discord 私信的正在输入提示显示在群里 | 获取 typing 目标频道时未区分场景，退回到了默认的群频道 | 私聊场景通过获取私信会话或创建用户 DM 通道单独触发 typing |
| Hermes shell hook 无法实现硬拦截沉默 | Hermes 的 shell hook 对 `transform_llm_output` 的返回值不予采纳 | 改写为 Hermes 插件，利用内部转换钩子在额度为 0 时换成 `[SILENT]` |
| 两个会话并发写坏跨渠道进度 | 水位共用同一个 json 文件，桌面和群同时注入会互相覆盖 | 水位按会话分文件记，各写各的，并兼容旧文件迁移（`9397056`） |
| 醒来轮同一番话说两遍 | 醒来提示词让模型既用 `send_message` 发了手机，又在桌面回复里把原话念了一遍 | 醒来提示里明确约束：用 `send_message` 说过的事桌面上不再重复（`0e5b38d`） |
