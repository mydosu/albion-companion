# 07 长期记忆：让她记得住，又不乱记

目标：我隔几天再来，她还记得我们聊过什么、我提过什么；但不会把没发生过的事当成真的，也不会把旧事翻出来盖过我现在说的话。

我用的记忆后端是 OpenViking：一个本地跑的服务，负责存、抽取、按语义检索。这篇不讲它的内部实现，讲的是**怎么把它接到一个角色的脑上**，以及接上以后我踩的坑。坑大多不在服务本身，而在「什么该记、什么不该记、记下来的东西怎么回到对话里」。

## 先看整体怎么搭的

```
壳（Windows）──聊天──> 脑宿主 :8650（WSL，bin/server.py）
                          └─ 常驻 pi 子进程
                              ├─ albion-turn.ts    每轮开口前：召回 → 拼进这一轮的 user 消息
                              ├─ openviking.ts     每轮结束后：捕获 → 写进 OV 的 session，攒够了 commit
                              ├─ albion-self.ts    她自己的心事本（notebook）
                              └─ albion-history.ts 翻聊天原话（chat_search）
                                        │ HTTP
                                        ▼
                      OpenViking 服务 127.0.0.1:1933（Windows，D:\AI\openviking）
                          ├─ embedding 模型：把文字变成向量，检索用
                          └─ vlm 模型：从对话里抽取记忆，异步跑
```

几个位置：

| 东西 | 在哪 |
|---|---|
| OpenViking 服务 | Windows，`D:\AI\openviking\`，监听 `127.0.0.1:1933`，数据在它的 `data/` 下（我这里约 926 MB） |
| 脑 | WSL 里的 `/root/albion-pi/`，仓库里的镜像在 `integrations/pi-brain/` |
| 脑怎么连服务 | WSL 里直接访问 `127.0.0.1:1933`，我这台机器上是通的（实测 `/health` 返回 200）；地址和密钥放 `agent/.env`，不写进代码 |
| 召回 | `agent/extensions/albion-turn.ts` 起一个 `python3 bin/memory.py --call recall`，纯标准库，不装 SDK |
| 捕获 | 官方的 OpenViking Pi 扩展，`agent/extensions/openviking.ts` 只是一行转发，主体放在 `agent/openviking/` |

**记和取是两条分开的路**。我是先自己写了召回，后来捕获换成官方扩展，召回没换（原因见下面「坑」）。所以你会在代码里看到两套东西并存。

## 什么时候记、记什么

**每一轮对话结束，官方扩展自动把这一轮写进 OpenViking 的一个 session**，session 名是 `pi-<会话 id>`。攒够 **8 轮或 20000 token** 就 commit 一次，交给服务端的抽取器。抽取是异步的，过一会儿才会在记忆池里长出东西：按类型分目录，有事件（events，路径里带 `YYYY/MM/DD`）、案例（cases）、偏好、实体这些。

她的池子是 `viking://user/<她的用户名>/memories`。

### 不是说过的话都该记

一开始我什么都提交，后来发现**有一类内容绝对不能进去：脑自己拼进对话里的东西**。每一轮她看到的 user 消息里，除了我打的字，还有宿主和扩展加的料。这些要在提交前剥掉：

| 脑自己拼的段 | 为什么不能提交 | 怎么处理 |
|---|---|---|
| 她自己醒来的提示词（里面念了心事本、上次定的事） | 它以 user 身份发出，抽取器会当成「我说的」 | 整条不提交 |
| 宿主补问「把刚才的话说完」 | 同上 | 整条不提交 |
| 会话重启时宿主接上的旧对话 | 旧话会被当成新话再抽一遍 | 只留「现在」之后我真打的字 |
| 召回块 `<memory-context>` | 把记忆再记一遍，越滚越大 | 剥掉 |
| 每轮的说话约定 | 那是给她的规矩，不是对话 | 剥掉 |

做法是官方扩展自带的 `OPENVIKING_CAPTURE_FILTERS`：一串 sed 风格的规则，宿主（`bin/server.py` 的 `CAPTURE_FILTERS`）启动 pi 的时候塞进环境变量。规则里不能出现英文逗号，因为是按逗号拼成一条变量的。

## 什么时候取、怎么注入

**每一轮开口之前取一次**，在 `albion-turn.ts` 的 `context` 钩子里：

1. 拿我这一轮的原话当查询（少于 5 个字不查）。
2. 调 `memory.py` 的 `recall`，向服务发 `POST /api/v1/search/find`，多取一些候选（`limit` 的 10 倍，最少 60 条）。
3. 按来源过滤（见下一节），再按分数筛、去重、排序。
4. 前几条拿完整正文，其余用摘要，总长不超过上限。
5. 包成 `<memory-context>` 块，拼到这一轮 user 消息里。

我用的参数，都可以用 `OPENVIKING_RECALL_*` 环境变量改：

| 项 | 值 | 说明 |
|---|---|---|
| 最多几条 | 6 | |
| 分数门槛 | 0.15 | 官方扩展自己的默认是 0.35、10 条，比我这套严 |
| 注入总长 | 4000 字 | |
| 读完整正文的条数 | 2 | 只有 level 2 的条目或没有摘要的才读 |
| 整个召回的时限 | 30 秒 | 单次请求 25 秒 |
| 排序 | 服务给的分数 + level 2 加 0.12 + 关键词重合最多加 0.2 | |

### 注入块长什么样

```
<我这一轮说的话>

<memory-context>
[System note: 下面是召回的记忆，不是新输入。它们是事后写的摘要，可能是错的；
 我现在说的话优先于它们；别主动翻旧事，除非正好和现在聊的有关。]
（代码里这段是英文）

## OpenViking Context
- [events]
  <uri>viking://user/<她>/memories/events/2026/10/29/xxx.md</uri>
  （10-29，2天前）
  ……摘要正文
</memory-context>

【本轮说话约定】……
```

顺序是**我的原话 → 回忆 → 约定**，约定放最后，离模型最近。回忆放在约定后面是我踩过的坑（见下）。

两个细节：

- **带日期**：events 的路径里本来就有日期，我把它换算成「（10-29，2天前）」放在每条前面。不然她分不清哪条是昨天的、哪条是三周前的，一条旧事会被当成「刚才的事」。
- **失败当没有**：服务挂了、超时、解析不了，都当没召回到，照常回话。这样记忆服务出问题，她只是变健忘，不会变哑。

我在生产上量了一下：同一个查询第一次 2.05 秒，第二次 0.54 秒，拼出来 3661 字。

召回是同步等的，所以时限很重要：服务卡住的最坏情况，是每一轮多等 30 秒才开口。

### 召回为空，先查这几处

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一句很短的话从不召回 | 查询少于 5 个字不查 | 正常 |
| 明明记过，一条都召回不出来 | 来源限制把它滤掉了：不在她自己的池子，也不在白名单里 | 看这条的 URI，确认在 `OPENVIKING_RECALL_SCOPES` 或 `recall-allow.txt` 范围内 |
| 有召回但很少 | 分数低于门槛 0.15，或被去重 | 调 `OPENVIKING_RECALL_SCORE_THRESHOLD`，再看 `--selftest` 的输出 |
| 一直为空，日志里有 `recall failed` | 服务不可达、key 不对或超时 | `curl` 一下 `/health`，再看日志 |

### 她自己也能主动查

官方扩展带 16 个 `openviking_*` 工具（`find`、`search`、`read`、`list`、`remember`、`forget` 这些），她想不起来的时候可以自己翻。**主动查不受下面的来源限制**。

## 记忆池里是谁的记忆

OpenViking 是个通用的记忆服务，同一个实例里可能还有别的东西：你自己的开发会话、报告、别的 agent 的空间。如果召回不限来源，它们全会被搜出来。

我的做法：

- **召回只放行她自己的池子**（`viking://user/<她>/`）。其余的来源要放进 `state/recall-allow.txt`（一行一个 URI）才会被召回；没有这个文件就一条都不放。想改范围用 `OPENVIKING_RECALL_SCOPES`。
- **只有真实对话会话才写记忆**。会话名单在 `agent/real-sessions.json`，我这里只有桌面和命令行两个。其他会话（探针、验收、自检脚本）一律算 ephemeral：
  - 启动 pi 时设 `OPENVIKING_BYPASS_SESSION=1`，官方扩展整段跳过，不提交；
  - 它们的心事本、自我安排、待办、最近一轮的注入留档都写到 `/tmp/albion-pi-ephemeral/<会话>/`，不碰生产的状态文件；
  - 给它们的工具只剩只读的那几件。
- 没带会话名的手工运行按生产算。宁可漏判一次手工调试，也不改桌面那只的路径。判断集中在 `agent/lib/session-scope.ts`，宿主和扩展用同一份。

新增一个真实渠道（比如手机端）时，要把会话名加进 `real-sessions.json`，否则它会被当成探针，什么都记不住。

## 记忆、心事本、聊天记录，是三样东西

| | OpenViking 记忆 | 心事本 notebook | 聊天记录 `chat_search` |
|---|---|---|---|
| 谁写 | 抽取器从对话里抽，自动 | 她自己调工具 add / done | 每轮自动落进活动库 `state/state.db` |
| 存在哪 | OpenViking 服务（Windows） | `state/notebook.json`（WSL） | `state/state.db`（WSL） |
| 怎么读 | 每轮按这句话的语义召回 | 每次醒来，把没划掉的整本念给她 | 她需要时按关键词查，最多 8 条，带北京时间 |
| 擅长 | 抓大意，跨很久 | 她惦记的、下次想跟我说的事 | 原话、准确的时间 |
| 不擅长 | 原话、准确时间 | 容量：没划掉的最多 30 件 | 语义 |

分工的理由：OpenViking 的召回是语义的，抓大意很准，但「我哪天说过那句话」它答不准，所以加了 `chat_search` 去活动库里按关键词翻原话。心事本是她**主动**记的，不经过抽取器，醒来提示词里念的心事本不会被提交回 OpenViking（见上面的剥离表）。

## 部署和配置

### 服务端

OpenViking 是个 Python 包（pip 装），装进一个独立的 venv，用 `openviking-server --config ov.conf` 启动。`ov.conf` 里要填的项：

| 配置项 | 干什么 |
|---|---|
| `storage.workspace` | 数据目录 |
| `server.host` / `server.port` | 监听地址，我用 `127.0.0.1:1933` |
| `server.auth_mode` / `server.root_api_key` | 用 API key 鉴权，key 自己生成 |
| `embedding.dense.*` | 向量模型：provider、api_base、model、dimension、api_key |
| `vlm.*` | 抽取用的对话模型：provider、api_base、model、api_key |
| `vlm.credentials` | 一串备用凭据，前面的失败会往后跳 |
| `memory.custom_templates_dir` | 自定义记忆模板 |

模型和 key 填你自己的，embedding 的 `dimension` 要和你选的向量模型一致。`curl http://127.0.0.1:1933/health` 返回 `healthy: true` 就是起来了。

### 脑这边

`agent/.env` 里需要这几项，值留给你自己填：

| 变量 | 作用 |
|---|---|
| `OPENVIKING_ENDPOINT`、`OPENVIKING_URL` | 服务地址。召回脚本读前者，官方扩展读后者，两个要写成一样 |
| `OPENVIKING_API_KEY` | 服务的 key |
| `OPENVIKING_ACCOUNT`、`OPENVIKING_USER`、`OPENVIKING_AGENT` | 租户信息，决定记忆写在谁名下 |
| `OPENVIKING_AUTO_RECALL` | 设成 `false`，关掉官方的自动召回 |

官方扩展我装的是 `openviking-pi-extension` 0.4.13，装在 WSL 的 `/root/albion-pi/agent/openviking/`，只有一个依赖（`@modelcontextprotocol/client`，`npm ci` 装 13 个包）。仓库里不放它的源码，只记来源和装法（`integrations/pi-brain/agent/openviking/来源与配置.md`）。

两个装的时候的坑：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 官方一键安装在我这直接拒绝 | 它只认 macOS 和 Linux，在 Windows 的 MSYS 里被挡；而 WSL 又看不到 Windows 那边 agent 的配置目录 | 照官方文档手工装 |
| 从 GitHub 拉不下来 | 我这台机器 clone GitHub 不通 | 从官方文档站下发行包 |

### 怎么验

```bash
# 1) 捕获：session 落盘了没有
find <openviking 数据目录>/viking/<账号>/user/<用户>/sessions -newermt "<今天>" -type f | head
#    → 能看到 pi-<id>/messages.jsonl、memory_diff.json 这些

# 2) 召回：直接跑一次，看用时和长度（别把输出整段贴出去，里面是真记忆）
python3 bin/memory.py --selftest

# 3) 工具面：让她用一个只有官方才有的工具，比如 openviking_list
```

## 服务挂了怎么办：守护

记忆服务是个常驻进程，会自己退出，也会因为上游额度、key 出问题而「活着但不干活」。我给它做了四个脚本的守护，脚本在 `tools/`，说明在 `tools/OPENVIKING_GUARD.md`：

| 层 | 脚本 | 做什么 |
|---|---|---|
| 恢复 | `openviking-recover.ps1` | `Ensure` 模式：`/health` 不是 200 才动手。停掉旧进程 → **先把整个数据目录冷备一份** → 拉起服务 → 最多等 180 秒（每 5 秒探一次 `/health`）。失败按 2、4、8、16、30 分钟退避。`Force` 模式跳过健康检查和退避，手工重启用 |
| 采样 | `openviking-memory-health.py` | 查服务端的任务列表（`/api/v1/tasks`），看 24 小时内有没有**比最近一次成功更新**的 commit / 抽取失败；服务不可达、抽取失败、进程退出分三个固定的事件槽，一共 8 秒预算 |
| 告警 | `openviking-notify.py` | 单消费者，发之前再确认一次现在是不是真有问题，同一件事 30 分钟内不重发。我让它直接发到聊天软件（Telegram 和微信两路，各自独立发、各自记日志） |
| 观察 | `openviking-observe.ps1` | 盯着服务进程，记下它什么时候退出、退出码是多少 |

整套挂在一个每 2 分钟跑一次的计划任务上。恢复脚本有互斥锁；要手工维护的时候，在 `.openviking-maintenance` 文件里写 `active`，`Ensure` 就会跳过，免得你正改着它又被拉起来。

测试在 `tests/openviking/`：隔离的单测只创建自己的短命进程，不碰真服务；在线验收需要明确授权。

## 踩过的坑

### 一、捕获和召回怎么接

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 换了新脑以后，记忆池从 10-07 起就不长了 | 旧脑的写入链路没跟过来，新脑没有「每轮自动记」的环节 | 接官方扩展做捕获，10-09 14:18 起重新落盘（我是看 `sessions/pi-*` 下有没有新文件确认的） |
| 一轮里出现两份回忆 | 官方扩展自己也会召回一次，加上我的，两份 | 官方的自动召回关掉（`OPENVIKING_AUTO_RECALL=false`），只留我的 |
| 回忆接在约定后面，旧话题压过我现在说的 | 我的回忆块原先拼在约定之后（10-08 发现），检索到的旧话离模型更近；官方那次注入同样排在约定后面（扩展按文件名字典序跑，`albion-*` 在 `openviking*` 前） | 顺序固定成原话 → 回忆 → 约定；回忆块的说明里写明「我现在说的优先」「别主动翻旧事」 |
| 召回悄悄失败，回话照常，没人发现 | 失败当没有，这是我故意的，但日志太省 | 日志里 364 次 `recall failed`，全在 10-07 到 10-17，之后没有。可惜日志只截了错误的**前** 300 个字，看到的全是 Traceback 的开头，最后那行真正的异常被截掉了，当时是哪种错没法回头查。记错误要记末行 |

### 二、池子里混进了不该有的东西

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 10-14：她的回忆里出现了讲「她是怎么被调教的」开发笔记，读着像被下令、被监视 | 同一个实例里还有我的开发会话记忆、开发报告资源，召回当时不限来源 | 召回只放行她自己的池子；顺手整理了一遍池子，删掉 76 条（开发会话、测试痕迹、探针对话），**全文先备份再删** |
| 旧脑留下的 1400 多条整个放进来，里面混着开发调试、别的项目、别人的消息 | 旧脑是个通用助手，空间没分过 | 不整段放行，用白名单逐条放：模型分类，再用规则复筛，去掉开发味的、别人的 |

### 三、编造被记忆固化（这是最难缠的一个）

10-25 之后她开始反复问我实验做得怎么样，可我根本没做过那个实验。查下来是一条链：

1. 我用脚本在**生产脑**上测口癖，台词是「今天好累，做了一下午实验」「考砸了」这类日常话。
2. 测试会话和桌面会话共用同一个心事本，台词被当成我说的，记进了心事本。
3. 她每次醒来都会把心事本念一遍，于是反复问。
4. 醒来提示词本身又以 user 身份被提交，抽取器把它抽成了「我做了一整天实验」的假事件，之后每轮召回再把它喂回去。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 她反复提一件我没做过的事 | 探针台词进了共享的心事本和 OpenViking | 名单制的会话隔离：只有真实会话写状态、写记忆（上面「记忆池里是谁的记忆」）；提交前剥掉脑自己拼的段（上面「不是说过的话都该记」） |
| 已经污染的数据 | | 心事本 5 条测试台词、2 条假事件删掉，**先备份**；之后在 3 个新会话里查编造，没再编出前几天的事 |
| 想怪抽取模型 | 抽取走 `vlm` 配置，实际抽取的 token 约 61% 是 beam 跑的，35% 是 DeepSeek，4% 是 minimax；那两条假事件一条是 beam 写的，一条是 DeepSeek 写的 | 是输入被污染，不是模型的错。DeepSeek 的口癖在抽取摘要里占得很少（events 5/191，preferences 1/13），所以没给她单独配抽取模型 |

教训：**测试会话和真会话共用任何一份「她的状态」，早晚会出事**。会话 id 各自独立没有用，心事本、记忆池都是全进程共享的。

### 四、她自己的口癖被召回喂回来

压过一次口癖以后，隔几天又冒出来。查来源，记忆库里存着她以前的原话，口癖就在里面，召回把它们原样带回来，她看到了就照着说。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 几个已经压下去的口癖词又出现 | 记忆里存了她当年带口癖的原话 | 先查来源再动手：查了几条，1 条是照搬召回里的原话，1 条是被召回推了一把，3 条召回里一个字都没有，是模型自己写的。所以改记忆只解决一部分 |
| 全库搜出 23 处 | 其中 10-25 之后新写的只有 4 处，主要是老存量 | 把这些原话改写掉，用批量写入的 upsert 写回 7 个事件文件，改前备份。语言相关的改写我交给更不带口癖的模型 |
| 记忆里有口癖，要不要删 | | 不删，改写。删记忆会丢事实，改写只换说法 |

### 五、旧事被当成现在

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一条几天前的旧事，被她当成「刚才的事」 | 召回和心事本里的条目没有时间 | 召回块里 events 带「（月-日，N天前）」；心事本一行带「#编号（月-日 记，几天前）」；每轮约定第一行报一次现在的日期、星期、时段和「他上一条消息是多久前」 |
| 她把约定第一行的时间原样念给我听 | 那一行没说是给她自己看的 | 在那行末尾加上「这些我心里有数就行，他问起来再像平常聊天那样说」 |

### 六、服务和守护

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 10-28 18:17 起约一小时，脑、翻译、OpenViking 抽取全部 401 | 我换了一处的 key，生产上用同一把 key 的地方有好几个，没一起换 | 换 key 要一次改全；失败的会话用补提脚本重新抽（先 `--dry-run`）。补提脚本要看清它写死了谁的身份，别拿通用的去补，会记错主人 |
| 抽取失败累积到 12 个 | 抽取用的两把 key 额度不足 | 不往模型本身上排查，先看额度。另外 `vlm.credentials` 里有两条长期认证失败的凭据，我没清，每次抽取都白跳两次；你的配置里失效的凭据最好删掉 |
| 服务退出过两次 | 没留下退出码和栈，根因没定案 | 没有盲改，只补了被动取证：观察器记退出码、每 5 分钟心跳、日志 5 MB 轮转 |
| 守护发了告警，我在该看的地方一条都看不到 | 告警原来是让一个 agent 带模型写一条再发，发到一个只有它自己的桌面端才显示的会话里；7 次投递 0 次成功，其中 4 次是超时 | 告警不经模型，直接发到聊天软件：退出码就是平台回执，不占额度。改完生产上实测一条真实告警，退出码 0 |
| 服务早就恢复了，守护却一直在跳过 | 恢复脚本在等它启动的子进程关掉输出管道，而服务进程一直握着这个管道，这一轮永远不结束，锁不释放 | 用临时文件接收输出，只等脚本自己的进程；测试里专门造一个一直握着输出句柄的子进程来验证 |
| 恢复后短暂退出的那一次没被通知 | 采样器只在「现在不可达」时才查退出事件 | 无论现在是否健康，都从观察器日志里取最近 5 分钟内确认过的退出，发带「当前已恢复」标注的历史通知 |
| 恢复快照越攒越多 | 每次恢复前都冷备整个数据目录，攒了 6 份旧快照 | 只留最新一份，其余删掉 |

## 你可以怎么做

想给自己的角色接上长期记忆，最少要这几步：

1. **起一个 OpenViking 服务。** 建 venv，`pip install openviking`，写 `ov.conf`（数据目录、监听地址、API key、一个 embedding 模型、一个抽取用的对话模型），启动，`/health` 通了为止。
2. **给角色一个独立的账号和用户。** 在 `.env` 里设 `OPENVIKING_ACCOUNT`、`OPENVIKING_USER`，别和你自己的开发会话共用一个池子，不然召回会把它们一起搜出来。
3. **做捕获。** 每轮对话结束，把「我说的、她回的」作为 message 写进一个 session（`POST /api/v1/sessions/{id}/messages`），攒几轮后 commit（`POST /api/v1/sessions/{id}/commit`）。`bin/memory.py` 里的 `remember()` 是个二十行的最小写法，直接抄。官方扩展做的是同样的事，外加按轮数自动 commit。
4. **做召回。** 每轮开口前，拿我的原话调 `POST /api/v1/search/find`，按分数筛、去重，拼成一个带「这是回忆，不是新输入」说明的块，放在我的原话**后面**、你的说话约定**前面**。超时和报错一律当没有。
5. **从第一天起就隔离测试。** 名单制：只有真实会话写状态、写记忆，其余全部只读。提交前把你自己拼进对话里的提示词、回忆块、约定剥掉，只留用户亲口打的字。这一步我是出了事才补的，事后清起来比一开始做麻烦得多。
6. **给召回限范围。** 默认只放行角色自己的池子，别的要加白名单。
7. **带上日期。** 召回出来的每一条都标上是几天前的事。
8. **最少的守护。** 一个定时任务，探 `/health`，不是 200 就停掉重起；重起前先备份数据目录。告警直接发到你看得到的地方，别绕模型。

做完这些，她就有了能跨天的记忆。心事本、聊天记录检索、各种工具是之后再加的，不影响前面这条链路。

## 经验

- 记忆不是存得越多越好。**写进去的每一句，以后都会被当成事实读回来。** 所以先管入口：什么该记，什么不该记。
- 她自己拼进对话的东西、测试的台词，都不是「我说过的话」，不要让抽取器看到。
- 记忆会放大错误：一次编造被记下，之后每轮召回都在重复它。出问题先查来源，再决定改记忆、改规则还是删。
- 改记忆之前先备份，能改写就不删。
- 召回失败要不影响回话，但一定要在日志里留下能定位的信息。
- 同一个服务里的东西不要混着用。池子分开，召回限定来源。
