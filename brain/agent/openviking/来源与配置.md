## 为什么只拿一半（捕获 + 工具面），召回不换

| 能力 | 开关 | 我们的选择 |
|---|---|---|
| 自动捕获（每轮入 session、commit 给抽取器） | `autoCapture`（默认 true） | ✅ **用**：迁移后她池子从 10-07 就停住了，这一条正好补上（实测 10-09 14:18 起重新落盘） |
| 服务端工具面（`openviking_*` 16 个） | `mcpEnabled`（默认 true） | ✅ **用**：我们手写的 `viking_search`/`viking_remember` 已删（`agent/extensions/viking.ts` 留档 `archive/context-cleanup-20261007/viking.ts.bak`） |
| 每轮自动召回 | `OPENVIKING_AUTO_RECALL`（默认 true） | ❌ **关**（`agent/.env` 里置 false）：两个来源会在一轮里塞两份回忆，而且官方那次注入排在我们的"约定收尾"**之后**（扩展按文件名字典序跑，`albion-*` 在 `openviking*` 前），会把 codex 定的口径打乱 |
| Context takeover（把已 commit 的历史换成归档 overview） | `OPENVIKING_TAKEOVER` | ➖ **默认 false，不动**：我们的历史是壳每轮重发 + 宿主长驻 Pi 线程，takeover 会改写这层语义 |

其余默认即可（值得知道的几个）：`scoreThreshold 0.35`／`recallLimit 10`／`recallTokenBudget 2000`（比我们那套 0.15/6/4000 字更严更省）；
捕获 `commitTurnThreshold 8` 轮或 `commitTokenThreshold 20000` 就 commit；会话开场注入 profile + `<available-skills>`（预算 10000/1200 token）。

配置来源优先级（官方）：**env → 工作区文件 → `ovcli.conf` 的 `plugin.pi` → 默认值**。
她走的是 env（`agent/.env`）：`OPENVIKING_URL`（= 原 `OPENVIKING_ENDPOINT`）、`OPENVIKING_API_KEY`/`ACCOUNT`/`USER` 沿用，
`OPENVIKING_AUTO_RECALL=false`。

## 怎么验（2026-10-09 实测）

```bash
# 1) 捕获：池子会不会重新长（她是 viking://user/albion/memories）
find D:/AI/openviking/data/viking/default/user/albion -newermt "2026-10-09" -type f | head
#   → sessions/pi-<id>/messages.jsonl、memory_diff.json、history/archive_001/…（真落了正文）

# 2) 工具面：让她用一个只有官方才有的工具
cd /root/albion-pi && pi -p "用 openviking_list 看一眼 viking://user/albion/ 下面有什么" --no-session --tools "*" -e agent/extensions/*.ts
#   → 她报出六个目录（memories/peers/privacy/resources/sessions/skills）

# 3) 整链路：bash accept.sh（基线见 D:/AI/Wife 仓库外的 accept-*.txt；插件上线前后都是 9/9）
```

## 回退

```bash
cd /root/albion-pi
mv agent/extensions/openviking.ts archive/ && mv agent/openviking archive/     # 关掉官方扩展
mv archive/context-cleanup-20261007/viking.ts.bak agent/extensions/viking.ts   # 把自己那两个工具拿回来
bash stop.sh && bash start.sh
```
（若不回退 `viking.ts`，她只是少了 `openviking_*` 这一层工具——召回与捕获都不受影响，而捕获也会一并消失。）
